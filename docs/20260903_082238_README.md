# Collection and Visualization of Crime Statistics and Resident Population by Prefecture and Nationality

Verify trustworthy data sources; regularly collect nationwide crime statistics and resident populations by nationality, prefecture, and region; and publish counts plus reproducible public-data-derived reference ratios on GitHub.

日本語版: [README.ja.md](./README.ja.md)

## Background
Public data on resident populations and crime statistics are fragmented across publishers and may not share the same geographic, temporal, or nationality definitions. The project responds to the harm caused when nationality labels circulate without fair quantitative context: it collects the available numbers accurately, makes non-comparability visible, and supports fact-based responses without treating nationality as an inherent risk trait. The detailed framing and cautions are maintained in [docs/brief.md](./docs/brief.md).

## Goals / Milestones
1. Audit primary sources and define comparable metrics.
2. Build a provenance-preserving collection and normalization pipeline.
3. Publish counts and source-pair-specific reference ratios, always showing their numerator, denominator, formula, provenance, and mismatches.

## Approach
Use everyone residing in Japan—not Japanese nationality—as the primary regional reference population. Treat each numerator/denominator pairing as a separately named indicator. Preserve both official definitions, calculate only observable combinations, expose mismatches, and never present a project-derived ratio as an official or exact crime rate. Nationality-specific views are secondary descriptive views, not labels of group essence or individual risk.

## Usage
Create a project-local environment and install the package with development dependencies:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
```

Run the verified quality gate and inspect the complete offline pipeline:

```bash
.venv/bin/python -m pytest --cov=nationality_crime_atlas --cov-report=term-missing
.venv/bin/nca-pipeline --help
```

Acquire one pinned official edition directly from its registered HTTPS URL:

```bash
.venv/bin/nca-acquire --source-id S08
.venv/bin/nca-acquire --source-id S15  # all-person prefecture crime context
.venv/bin/nca-acquire --source-id S16  # October 1 total population context
.venv/bin/nca-acquire --source-id S08 --refresh  # explicitly recheck remote content
```

The default command reuses an existing validated edition without network access. `--refresh` downloads again, reuses identical content, and stops on a hash change. A successful run updates the machine-readable JSONL and human-readable CSV artifact catalogs.

Generate a timestamped label/category mapping audit from every validated catalog input:

```bash
.venv/bin/nca-map-dimensions
```

This writes JSONL, CSV, and a provenance-rich summary under `data/processed/_mappings/<timestamp>_dimension_mapping/`. Mapping status deliberately does not imply that a crime numerator and population denominator are statistically compatible.

Generate a timestamped indicator data product from the validated catalog and latest reviewed mapping:

```bash
.venv/bin/nca-build-indicators
```

This writes immutable JSONL/CSV records and a provenance-rich summary under `data/processed/_indicators/<timestamp>_indicators/`, then atomically updates `latest.json`. Calculated values remain public-data-derived reference ratios; they are not official or exact crime rates. The current output also carries `small_number_warning_policy`, row-level `small_number_warning_flags`, and `default_ranking_excluded` for the approved non-suppressing warning heuristic.

Generate the separately pinned all-resident regional-context product:

```bash
.venv/bin/nca-build-all-resident-context
```

This writes immutable JSONL/CSV records and a provenance-rich summary under `data/processed/_all_resident_context/<timestamp>_all_resident_context/`, then atomically updates `latest.json`. The run includes three calculated context families (`recognized_cases`, `cleared_cases`, `cleared_persons`), plus explicit refused rows for published police-region/subregion geographies and for unpublished Japanese-nationality or individual-nationality prefecture numerators.

Build the compact dashboard export from the resolved latest indicator and all-resident products:

```bash
.venv/bin/nca-build-compact-export
```

This writes `dashboard_export.json`, `summary.json`, and an export-level `latest.json` under `output/compact_export/<timestamp>_compact_export/`. Schema v2 reads and hashes the same source bytes, retains row-to-definition IDs, reconciles source summaries to records, exposes only whitelisted public source metadata, and atomically publishes a hash-closed pointer. The UI therefore does not depend on a later-moved source pointer or a private local path.

Run and verify the local visualization against the currently reviewed static bundle:

```bash
cd web
npm install
npm run generate:map
npm run test:coverage
npm run typecheck
npm run lint
npm run build
npm run dev
```

`web/public/data/dashboard_export.json` is a pinned publication copy, not a new source of truth. It currently matches the reviewed compact export byte-for-byte. Automatic synchronization and external publication are intentionally deferred until the M4 publication lane is selected.

Audit candidate denominator and numerator thresholds against the current pinned indicator run:

```bash
.venv/bin/nca-audit-small-numbers
```

This writes an immutable sensitivity matrix and the exact resolved `indicator_input_manifest.json` under `data/processed/_indicator_sensitivity/<timestamp>_small_number_sensitivity/`. Its config is explicitly `policy_status=sensitivity_only`; running it does not change canonical indicator records or approve a UI warning rule.

For an already acquired local official artifact, run the lower-level offline path with a timezone-qualified retrieval timestamp:

```bash
.venv/bin/nca-pipeline /path/to/official-file.xlsx \
  --source-id S14 \
  --retrieved-at 2026-08-30T09:00:00+09:00
```

The pipeline writes an immutable snapshot under `data/raw/<series>/<edition>/<timestamp>/` and promotes normalized JSONL plus manifests and a passing quality report under the matching `data/processed/` path. Direct registered-URL download is implemented; discovery of newly published editions and scheduled execution are not. Lower-level commands remain available as `nca-snapshot`, `nca-ingest`, and `nca-validate`.
