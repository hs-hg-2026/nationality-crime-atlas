# 一般読者向け日本語案内・情報設計の改訂記録

## 結論

ローカル画面は、データ表現に入る前に「何のためのサイトか」「何が分かるか」「何が分からないか」を読める構成へ改訂した。画面上に混在していた `cohort`、`nationality-neutral`、`context`、`strict`、`flow`、`stock` などの内部用語は、一般読者向けの表示から除いた。数値、出典、算出拒否、統計上の注意は削除していない。

## 発端

ユーザーから次の問題が指摘された。

- 日本語の文章に英語の内部用語が混ざり、意味を取りにくい。
- `cohort` は疫学を想起させ、このサイトの説明として唐突である。
- サイトの目的やREADMEへの導線が画面上で見えない。

これは単なる表記の問題ではなく、初見の読者が数値を見る前に目的と限界を理解できない情報設計上の問題と判断した。

## 変更内容

1. 画面冒頭に「このサイトについて」を追加した。
   - 国籍についての印象や決めつけではなく、公表値を確認する試作であることを明示。
   - 「まず地域全体」「次に国籍等別」「この数字だけでは分からないこと」の3項目で読む順番を提示。
   - 認知件数、検挙件数、検挙人員の短い用語説明を追加。
2. ページ内メニューを追加した。
   - このサイトについて
   - 地域全体
   - 国籍等別
   - 犯罪の種類
3. 日本語READMEと常設の解釈方針へ直接移動できるリンクを追加した。
4. 表示見出しと注意書きを平易な日本語へ変更した。
   - `総人口による地域 context` → `国籍で分けない、地域全体の状況`
   - `cohort`を使わず、`同じ事件を認知から検挙まで追跡した数字ではない`と説明。
   - `flow / stock`を、`1年間の犯罪件数 / 10月1日時点の人口`と具体化。
   - `heatmap`、`cluster順`、`source`、`warning / status`などを日本語化。
5. 出典カードを日本語化した。
   - 各source IDに対して、公表機関、資料名、対象年を日本語で表示。
   - 公表ページと元データへのリンクを維持。
   - SHA-256と取得日時は「取得記録を確認」の折りたたみ内へ移した。
6. 内部のwarning／refusal codeを、日本語の説明に置き換えた。
   - 内部コード自体は要素のtitle属性に残し、追跡可能性を維持。
7. `README.ja.md`も、リンク先で同じ問題が再発しないよう自然な日本語へ全面改訂した。

## 変更していない境界

- 表示する数値、分子、分母、計算式の意味は変更していない。
- 日本の値が全住民値から全外国人値を差し引いた参考値であることを維持した。
- 公表されていない国籍等別かつ都道府県別の値は推計しない。
- 同年の認知件数と検挙件数の差を「未解決件数」「未解決率」とは呼ばない。
- 小さい人口や少数の犯罪件数・人員を隠さず、変動しやすい旨を表示する。

## 検証結果

- 表示要件を先に追加し、旧画面で7件失敗するREDを確認した。
- 改訂後のdashboard component test：10 / 10成功。
- Web全体：69 / 69テスト成功。
- coverage：statement 90.63%、branch 84.34%、function 95.91%、line 91.78%。
- typecheck、lint、format check、公開データSHA-256検証：成功。
- production build：sandbox内では静的生成用socketが`EPERM`となったが、同一buildを許可環境で再実行し、1 routeの静的生成に成功。
- Chrome実画面：1440 × 1800 pxと500 × 900 pxで冒頭の情報階層と折り返しを確認。
